# Data sources — full detail

**SKILL.md carries a compact summary table.** This is the full per-script detail behind it —
what each reads, what it gives you, and every provenance/edge-case caveat measured against it.
Read this when the summary table isn't specific enough, or before trusting a particular
script's output on a question that matters.


**Start with `farm_snapshot.py`** — a briefing-shaped digest composed from the parsers below.
`collect_state.py` is the full raw snapshot, noticeably larger; reach for it when you need a
field the digest doesn't carry, or at onboarding. `--debug` on either gives unabridged output.

| Script | Reads | Gives you |
|---|---|---|
| `farm_snapshot.py` | (composes the parsers below) | **the briefing digest** — when, money, land, fleet (incl. **fuel/wear alert tiers**, see `check_fleet_alerts.py`), fields, contracts, **inventory** (what the farm holds and what it's worth), **input_costs** (the seed/fertilizer BUY calendar), **weeds**, **equipment_market**, **equipment_gaps**. **Machine questions** (what do we own, what can it do, can it spray herbicide) are answered from `fleet.machine_record.by_block` — each capability block with the machines that declare it and the fill types they take; a machine not listed is **not proof of absence**, and `unknown_vehicles` (encrypted DLC) were not readable at all. `--fleet-only` computes just `when`+`fleet` from 3 parsers instead of ~11 — ~10-15s vs ~55-90s on this install, for callers (`check_fleet_alerts.py`) that never need the rest |
| `collect_state.py` | (composes all parsers) | the full raw snapshot — bigger; onboarding, or when the digest lacks a field |
| `read_environment.py` | environment.xml | current_day (from `<currentDay>`), clock, season, days_per_period, weather + forecast |
| `read_economy.py` | **farms.xml + farmland.xml** | cash, loan, land ownership, via `--farm-id N` — **not** economy.xml, which holds only fillType price history and has no cash/loan/ownership data at all |
| `read_farm_ledger.py` | **farms.xml** | **b39 + b40**, emitted in the rev-4 **domain envelope** (`sections.finance_ledger`, `sections.lifetime_statistics`, `sections.lifetime_averages`). This was a shape probe built ahead of its ruling; **the ruling landed, the provisional shape is gone, and what ships now is the § 6.2 envelope** — §§ 7.1/7.2 are its worked examples. `finance_ledger`: the 33-category money ledger, five `<stats day=N>` slots — the direct answer to "where is the money going"; coerced to `float`, and a value that is non-numeric **or non-finite** (`NaN`/`Infinity` are not JSON numbers) is an error, never a coerced guess. `lifetime_statistics`: the farm's lifetime counters, emitted as **raw text** (they mix floats, ints and a zero-padded bitfield `treeTypesCut`, which numeric coercion would flatten to a wrong `0`). `lifetime_averages`: those same counters divided by `playTime` **in hours** — a `per_play_hour` rate as `float`, carried beside each counter's own `lifetime_total_raw`; the counters themselves stay raw in `lifetime_statistics` and nothing here re-types them, and **no unit is asserted for a counter whose unit farms.xml does not state**. The denominator ships with the section — `playTime` is **REAL minutes of play** (settled by measurement, not assumed), and `timeScale` is deliberately not applied because it is a mutable setting's snapshot rather than a lifetime property. A `playTime` that is missing, unreadable, zero or negative yields **no averages at all** rather than a substituted denominator, and a counter that will not parse is reported in `unreadable_counters` with its raw text rather than dropped. Farm-scoped via `--farm-id N` or `--farm-id=N`; an unrecognised argument is an error, never a silent fall back to farm 1. `finance_ledger` reads a **single-period land-cost read** element and so carries the mandatory `blocked_by` declaration (§ 6.8.2 tooth 1): the per-slot values ship, **no aggregate of them ever does**. **No rate, trend or "days until" is derived** — the `day` slot has no established calendar mapping and the savegame holds no history |
| `read_fill_prices.py` | **economy.xml** | **what every fillType sells//buys for, per period** — today's price, the peak, the whole 12-period curve. The only reader of economy.xml's price history, and **the** price source for valuing crops and costing seed/fertilizer |
| `read_game_defs.py` | install + **map mod** definitions | **which fillTypes are sellable OUTPUT vs buyable INPUT**, **seed litres/hectare per crop**, and **each crop's growth states** (which growthState numbers mean ready / dead / harvested) — read from the game's own categories, `<sprayType>` list, `<seeding litersPerSqm>` and `<foliageState>` lists. Map package first |
| `read_equipment_market.py` | sales.xml + `read_store_prices.py` | **used listings resolved to their real new price** — label, condition, discount. Turns `read_sales.py`'s raw list into "is this a bargain?" |
| `read_fields.py` | fields.xml + GRLE + `read_game_defs.py` | **`crop_state` per field — `ready`/`harvested`/`dead`/`growing`**, from growthState vs the crop's own foliage states. Plus `weedState`, ownership, and separate `harvested_on_owned_land` / `unknown_crop_state_on_owned_land` lists |
| `read_farmland_areas.py` | `infoLayer_farmlands.grle` in the map mod + farmland.xml + fields.xml + farms.xml | **b13, b14** — the `land` set, in the § 6.2 **domain envelope** (`sections.map_calibration`, `farmland_parcels`, `owned_land`, `field_ownership`). **Per-parcel hectares, value and owner**, decoded from the raster the engine itself reads — `FarmlandManager:getFarmlandIdAtWorldPosition` takes the same info-layer and derives area the same way, one `terrainSize/localMapWidth` factor on **both** axes, which is why gate 2 **refuses non-square pixels** rather than averaging them. Two hard gates run every time and the script emits **no** area or value figure when either fails. **The `<fieldPurchase>` cross-check ships DISABLED, not deleted** (`CROSS_CHECK_ENABLED`): that read was the single-period land-cost read defect — `find` returned one `<stats>` slot under a name promising a lifetime absolute — and `farms_xml_fieldPurchase_abs` is still blocked, so the corrected `findall`-and-sum read exists and is tested but **nothing calls it at runtime** and no section declares the blocked element. That corrected read **emits window coverage rather than assuming it**: a naive sum silently under-reports on a save whose stored window has rolled, so `covers_full_history` is the string `"unknown"` — the engine's retention policy is undocumented and a bool would have to lie in one direction. **⚠ Field ownership is now a MEASURED SPATIAL JOIN, not a design ruling — a HIGH-severity finding, 2026-09-04.** The savegame still carries no field→farmland link (a `<field>` has `id` plus crop state and nothing else — no area, no position, no farmland reference), and the engine's own runtime answer to *"which farmland contains this field"* — `FarmlandManager:getFarmlandIdAtWorldPosition` — consumes a **world position**, which an offline savegame parser does not have. But the map's own `map.i3d` authors every field as a polygon in that same world-coordinate space, and `resolve_spatial_field_farmland` replicates the engine's read offline: each field polygon's own AREA CENTROID (`polygon_area_centroid`), transformed world→raster via the engine's own `convertWorldToLocalPosition` formula (cited, FS25 Community LUADOC), sampled against the same `infoLayer_farmlands.grle` raster gate 1/gate 2 already validate. This **replaces the retired `ARCH-R3-04` identity assumption** (`field_id == farmland_id`, licensed only for `FS25_Montana_4X.MapMontana`, minted by the project owner 2026-08-05c) — measured FALSE on MapUS/savegame3, where the map's own field polygons and the save's own field ids overlap only 64 of 77. The new ruling, **`ARCH-R3-06`**, carries two measurements alongside itself, and **they corroborate the AREA, not the join's POSITION** (this sentence previously made the per-save claim unqualified, for the join as well as the area). `shoelace_label_check` (does this parser's own polygon-area formula — item 3, `shoelace_area_ha` — reproduce the map author's own printed `<Note text="fieldN\nN.NN ha"/>` label?) **can refute the join**: the sample is taken at the polygon's area centroid, so a provably wrong area means a provably wrong centroid. **Agreement refutes nothing about position** — a shoelace sum is invariant under rotation and translation, the two degrees of freedom the world transform consists of. `field_coverage` (do the map's and the save's field ids form the same set?) compares **id sets, never geometry**, and disclaims being a falsifiability check in its own docstring. The join's position rests on a **build-time cross-map regression** instead. A field with no map-side polygon still reports `farmland_id: null` with a reason, never a guess; a field whose polygon vertices sample more than one farmland id sets `straddles_farmland: true` on its row rather than silently picking a side. That section reports **`ok`** when every field resolved cleanly (verified live: 122/122 on Montana, 53/53 on Lone Star) and **`partial`**, naming how many did not, otherwise (MapUS/savegame3: 13 of 77) — no longer permanently `partial` the way the retired, permanently-unfalsifiable `ARCH-R3-04` forced it to be. The owned total is **`land_value`** — a current asset valuation, not a record of what was spent. Also emits a **legacy top-level block** (`owned`, `gates_passed`, `parcels`, `fields`) that `read_fields.py` still consumes; it is derived from the sections, never recomputed, and retires when that consumer migrates |
| `read_store_prices.py` | install `data/**` + mod zips | **store prices** for anything not yet owned — `--fleet`, `--lookup FILE`, `--search KEY`, `--gaps`, `--fuel-capacity` (each owned vehicle's real DIESEL tank capacity **and its machine record** — type, split category, the specialisation blocks its own XML declares, the fill types it takes with `fillTypeCategories` resolved across base, map and active mods, and a vehicle-type-override flag — all from its own store/mod XML in one pass; vehicles.xml carries neither. An encrypted-DLC vehicle is `record_status: unknown`, never guessed) |
| `read_vehicles.py` | vehicles.xml | equipment, filtered by `--farm-id` — `owned_count` vs `total_seen`, `owned_total_price`, and **cargo: what each machine CARRIES**, kept distinct from the fuel it runs on |
| `read_missions.py` | missions.xml | **all** contracts, offered and accepted — type, status, target field. Rewards are not in the file |
| `read_placeables.py` | placeables.xml | silo/storage **and their contents**, husbandry, production chains, filtered by `--farm-id` — `owned_count` vs `total_seen`, flags `unrecognized_farm_ids` |
| `read_livestock.py` | placeables.xml | **b10 — animal clusters**, farm-scoped via `--farm-id N`, emitted in the rev-4 **domain envelope** (`sections.animal_clusters`). All four `g_int` attributes — `age`/`health`/`numAnimals`/`reproduction` — are coerced to `int`, each against its own XSD citation; `subType` stays **raw text** because the XSD declares it a *name* (`COW_HOLSTEIN`) that merely reads like a code. Every row carries `placeable_id` (the placeable's `uniqueId`), declared in `identity_fields` and kept **raw** — an identifier is not a quantity — so two clusters in different barns stay distinguishable. **Zero animals is an ANSWER, not a gap**: the section is always emitted, reading `unknown_by_design` / `empty_means: farm_has_none` / `count: 0`, and an *absent* container is read as "this farm owns none" on the authority of ruling **`ARCH-R3-01`** — a `design_ruling`, never a schema fact, because the engine's emit-when-empty behaviour is undocumented. When every section is `unknown_by_design` the **domain** reports `unknown_by_design` too (§ 6.3.3 rule 2) |
| `read_storage_capability.py` | a placeable TYPE def + `maps_fillTypes.xml` | **what a silo can ACCEPT** — reads BOTH `fillTypes` **and** `fillTypeCategories` on every `<storage>` node and expands the categories . Reading only `fillTypes` was the "no silo accepts onion" false negative; an unresolved category is reported `unknown`, never `no` |
| `read_sales.py` | sales file | raw used-equipment listings (map-wide; no farm filter). **Prefer `read_equipment_market.py`** — a listing without a new-price comparison can't answer whether it's worth buying |
| `read_prices.py` | placeables.xml | per-station trade signals (map-wide). **Not a price source**: `meanValue` is `null` on anything never traded — use `read_fill_prices.py` |
| `read_career.py` | careerSavegame.xml | save-wide: map id/title, difficulty, initial money/loan, timeScale, autoSaveInterval, mod list |
| `read_productions.py` | placeables.xml | **b3, b4, b5, b6, b9** — the `production` set's factory half, farm-scoped via `--farm-id N`, emitted in the rev-4 **domain envelope** (`sections.production_lines`, `production_costs_to_claim`, `delivery_modes`, `pallet_spawn_cooldown`, `storage_fill_levels`, `greenhouse_auto_watering`). **Ownership is the whole ballgame**: 39 `<productionPoint>` exist on this map and only **16** are the player's — 10 are farmId=0 and 13 are farmId=15 map furniture, so an unfiltered read overcounts 2.4×. **An absent optional attribute is NOT zero**, and the XSD settles it: `storage/@fillLevel` carries `default="0"` so its absence *is* zero by citation, while `productionCostsToClaim` and `palletSpawnCooldown` carry no default, so absence is unlicensed and those rows are simply not emitted — the count of production points lacking the attribute goes in the section's `reason` instead. Where **no** production point carries `palletSpawnCooldown` the section reports **`unavailable`**, not a confident zero, which makes the domain `partial` on this save. `isEnabled` and `AutoWatering` ship **raw**: `g_bool` is a restriction of `xs:string`, and **no `xs:boolean` exists in any of the install's 88 XSDs**, so § 6.5's `bool` branch cannot be taken. The emitted record keys are snake_case — `is_enabled`, `auto_watering` — distinct from these raw XML attribute names; a consumer reading for the attribute name itself will not find it in the output. Storage reports fill **levels only — never a ceiling, so no "silo full" verdict** (b7's capacity is definition data this savegame-only reader does not open) |
| `read_bales_pallets.py` | **items.xml + placeables.xml + vehicles.xml** | **b19, b22, b23, b25** — the `production` set's bale/pallet half, farm-scoped, in the rev-4 **domain envelope** (`sections.loose_bales`, `object_storage_bales`, `pallets`, `baler_state`). Three sources, one `source_set_hash`: the domain is stale if **any** of the three moves. **`className` is a filter, not a label** — one object-storage container holds **9 bales and 24 vehicles** under the same `<object>` element, and the first six children are all bales, so sampling the head of the list overcounts 3.7×. Bale ownership reads the **object's own `farmId`** (the schema documents it as the owner farm), not the shed's, and every row carries the storing placeable's id and farmId so a divergence stays visible; on this save the two agree, so that choice is unobservable here and is made on the schema. **Stored bales carry no `uniqueId`** — zero of 33 do, and all nine bales share one identical attribute signature — so identity is `(storage_placeable_id, ordinal_in_storage)`, with the ordinal explicitly **not** stable across saves; declaring an always-null `unique_id` as the identity would be absence dressed as a key. `items.xml` being `<items/>` is a **present-and-empty container** (no loose bales) and is kept distinct from the file being missing, which is a could-not-run |
| `read_production_defs.py` | the **game install** + every **mod zip** — not the savegame | **b1, b2, b7, b8, b20, b21, b24** — the `production` set's definition half, in the rev-4 **domain envelope** (`sections.production_recipes`, `storage_capacities`, `greenhouse_recipes`, `bale_definitions`, `map_bale_set`, `pallet_definitions`). **This is the half that makes "silo full" computable**: the savegame records what a production storage *holds*, only the definition records what it *can* hold, so `read_productions.py` reports a level and refuses to imply a ratio while `storage_capacities` here carries the ceiling. Neither script computes the ratio — the join belongs to whatever consumes both. **Farm-independent**: `--farm-id` is accepted for interface consistency and **filters nothing**, which the envelope says out loud. Files are selected by **content, not filename** (the base game ships 503 placeable XMLs; 74 carry a `<production>`), and every row is keyed by **full path including the `zip!member` form** — four separate `maps_bales.xml` exist on this install, so basename keying would fuse different bale sets. Greenhouses are split out so a greenhouse's `<productionPoint>` is never counted in both b1/b2 and b8. **Everything ships raw**: no XSD covers `data/placeables`, so § 6.5 rule 2's citation cannot be made and rule 1's default stands — `capacity`, `amount` and `cyclesPerHour` are strings, and a consumer needing arithmetic owns the conversion. A file that will not parse makes the domain **`partial`** and its counts a declared floor, never a silent total |
| `read_weather.py` | environment.xml + the map mod's `config/environment.xml`, read from inside its zip | **b26, b27, b28, b29, b30, b31** — the `weather` set, in the rev-4 **domain envelope** (`sections.forecast`, `forecast_temperature`, `severe_events`, `ground_conditions`, `weather_type_weights`, `rain_presets`). `read_environment.py` emits only the first 5 forecast slots; this reads **all 30**, plus hail and twister events, ground wetness and snow height. **Weather is map-wide, not farm-scoped** — no element it reads carries a `farmId`, so `--farm-id` records *which farm the report is for* and **filters nothing**; do not read a `farm_id` here as evidence the figures were scoped. **It coerces nothing, and that is a measurement, not a shortcut**: there is no `savegame_environment.xsd` at all, confirmed by two structurally independent probes over all 88 XSDs (is the *element* declared · is the *attribute* declared), and no XSD anywhere declares `minTemperature`, `maxTemperature` or `rainfallScale`, so § 6.5 rule 2's citation cannot be made and rule 1's raw default stands. Raw also protects real data — `wetness="0.000000"` is a **fixed-precision zero**, a value rather than an absence, and coercion would blur it against a missing attribute. **b26 is a ruled reading and ships the evidence that would expose it wrong**: the temperature join (savegame slot → map-mod variation) is not documented, so the row carries its inputs rather than only its answer |
| `read_fleet.py` | vehicles.xml | **b18, b41** — the `fleet` set, in the rev-4 **domain envelope** (`sections.vehicle_configurations`, `livestock_trailer_occupants`). `read_vehicles.py` gives the fleet inventory; this gives the **per-vehicle configuration detail** that drives resale valuation and capability inference. **Ownership is not optional**: 141 `<vehicle>` exist and 114 are farm 1 — the other 27 are `farmId=0`, the map's own train rolling stock, and the first rows an unfiltered reader meets are the BNSF locomotive and its hoppers. **`isActive` is declared `g_bool` and still ships raw, which is not a rule-5 violation**: `g_bool` restricts `xs:string` with a `true\|false` pattern, never `xs:boolean`, so the guarantee § 6.5's hazard table demands does not exist and rule 5 never fires — and **every `g_bool` in every FS25 savegame schema behaves this way**, so this answer is inherited by every future domain rather than re-derived. **b18 reports `unavailable`, deliberately**: `minOccurs="0"` is *permission, not behaviour*, `ARCH-R3-01` is scoped to `husbandryAnimals/clusters` and stretching it by analogy is the laundering the `kind` field exists to prevent, and minting a new ruling is not a domain script's call — so the domain rolls up **`partial`** and says plainly that it cannot tell "owns no livestock trailer" from "owns one the engine wrote no element for" |
| `read_game_log.py` | the engine `log.txt` (resolved from the savegame's parent) | **structured log events** — errors and **mod-load failures**, warnings with their source, the available-mod inventory, session lifecycle, and a **clean-shutdown verdict** (`log_complete`: did the run end in `#End.`, or crash / still be running). Answers "did any mod fail to load, did last session crash?" without hand-grepping thousands of lines; `{"error": ...}` if no log. Read at briefing (`references/session-steps/s2-take-delivery.md`) |
| `check_mods.py` | a mod `.zip`, or a `mods/` dir | **mod-zip structural soundness** — zip opens, `modDesc.xml` at the root, declared icon / `extraSourceFiles` resolve, version/title present. Structure only, no Lua run; per mod `status: ok/issues`. Only a missing/unopenable `modDesc.xml` is a verified cannot-load — cross-check `read_game_log.py` for the game's actual verdict. Used at onboarding to confirm the notification mod is sound (`references/onboarding-steps/o4-bridge-check.md`) |
| `check_sanctum_freshness.py` | the sanctum + the save | **does the farm's memory still match reality?** Probes the interest rate, owned land, the offset and directive premises; fails when the sanctum contradicts the save. Run it at every briefing — it is fast |
| `project_crop_calendar.py` | the map's (else the base game's) crop foliage files + environment.xml + fields.xml | **planting windows per crop and ready / dead dates per owned field** — from each crop's `<growth><seasonal>` periods (`plantingAllowed`, per-period state updates) and the field's `growthState`. Every date is a **window** (`from_day`..`by_day`, plus `likely_day` and, for death, `alive_through_day`) because the engine's tick timing is native and is simulated under both readings; the document names its assumptions and the evidence counted in this run. A crop like potato, whose `isHarvestReady` sits on a state growth never reaches, is reported `needs_player_step` with its preparable and death windows and **no ready day**. A date it cannot work out is `unknown` with the reason. Use it to build the field plan; never hand-write a script for that. Read-only |
| `read_building_capacity.py` | placeables.xml + each owned building's **own definition file** (game install or mod zip, joined by the save's `filename`) | **how much each owned storage can hold, and how full it is** — silos, husbandries, production points and the rest, from the storage's total `capacity` and its per-fill-type rows (`Storage.lua`). Reports each fill type's ceiling and whether it is its own or the shared total (and the shared pool), so a percent is never computed against the wrong denominator. A building whose file cannot be opened is listed `unresolved` with the reason and **no figure**; exits non-zero if not one resolves. On demand and at D-11 — read-only |
| `check_skill_honesty.py` | SKILL.md + the parsers | **do this skill's own docs agree with its own code?** Two halves, kept as separate checks: doc/code parity (`check_reachability`, no savegame) runs automatically at **build** time (BG-1, `tools/build_package.py`) — a session never runs this half. Capability wiring (`check_honesty`, savegame-dependent) is **developer-facing**, run by hand at `references/dev-steps/step-04-check-skill-honesty.md` when `scripts/` or `SKILL.md` changed this development session — never part of a player session |
| `check_fleet_alerts.py` | `farm_snapshot.py --fleet-only` + `sanctum/fleet-alert-state.json` | **fuel/repair alerts, ON by default** (the script reads `config.json` `fleet_alerts_enabled` itself; no key means on, `false` means it sends nothing, writes nothing and prints `{"status": "disabled"}`) — diffs the fleet's fuel/wear tiers (fuel ≤50%/≤25% remaining, wear ≥50%/≥75%) against last-alerted state and pushes an individual `ack` card, via `notify_farm_manager.py`, for every NEW crossing only; recovering resets silently, no repeat card for an unchanged tier. Run at `BR` and on every live `EVENT savegame` — never `ST`/`PL`/`PR` (it writes state) |
| `notify_farm_manager.py` | (writes) the mod's bridge | **puts a message on the player's screen** while they play. Needs the AI Farm Manager 25 mod installed. Exit `0` = shown, `2` = nothing read it |
| `read_replies.py` | (reads) the mod's replies.xml | **ingests the player's card replies** into a durable sanctum ledger, then truncates the consumed file — the return half of the two-way loop. Dedup key `(id, action)`; loss-proof (ledger written before the guarded truncate). Exit `0` = ingested (or nothing waiting), `1` = malformed/corrupt (touches nothing) |
| `generate_state.py` | (composes the 7 envelope parsers) | **writes the cache** — fans out over the seven domains that emit the § 6.2 envelope, stores each one's output verbatim under a provenance triple in `cache/domains/<domain>.json`, rotates the prior generation into `cache/prev/`, and stamps `CACHE-VERSION`. The cache root is **derived** as `dirname(dirname(<config>))/cache`, with an optional `paths.cache_dir` override — no new required config key. A parser that **fails** is isolated: its domain is written `unavailable` with the exit text carried, and the other six still land. A parser that **exits 0 with zero sections** fails the whole run (§ 6.3.3 rule 0.5) — a false success is not survivable. The nine registered non-envelope domains are named in the output with a reason, never silently skipped. `--farm-id` is never defaulted; an absent, placeholder or unparseable `farm_id` is a structured error |
| `read_state.py` | `cache/domains/*.json` + the files each domain declared | **the cache gate, and the ONLY way to read the cache** — verification is inseparable from the read, and it **never silently regenerates**. Re-hashes every domain's own declared sources on every invocation. Exit `0` = the verified view, every domain carrying its own status, reason and provenance. Exit `1` and **zero farm data** for: `STALE` (with both hashes, what moved, the age and the exact remedy command), `CACHE ABSENT`, `CACHE EMPTY` (a valid `CACHE-VERSION` over an empty `domains/` **refuses rather than renders**), `CACHE VERSION MISMATCH`, and `CACHE FARM MISMATCH` (the cache belongs to a different farm). `--accept-stale` stamps **every** section, including the ones that verified clean — never a quiet degrade. **It also emits two blocks the cache does not contain**, both under `derived`: `production_input_demand`, the production input-demand join (`derive_production_demand`) computed in-process from `productions` + `production_defs` — the two halves no single parser can see — and `owned_land_crop_state`, the fresh-crop-state join (`derive_owned_land_crop_state`) computed from `fields`. Neither is **persisted**, because a stored derivation is a second copy of the truth that can drift from the first. `derived` is a **top-level sibling of `aggregate`**, deliberately outside it: a derived figure has no `json_path`, and putting one inside `aggregate` would start the claims manifest carrying figures it cannot re-resolve on disk. It carries its own `status` and its own source-currency marks, and every case it cannot compute — an unmatched line, an ambiguous rate, an absent stock row, a pass-through input — arrives as a row stating why, never as `[]`, `{}` or a dropped line. *(Vocabulary note: `CURRENT`/`STALE` here are the **cache-temporal** words, not the sanctum-structural `FRESH`/`STALE`/`UNVERIFIABLE` set that `sanctum_maintain.py` uses.)* |
| `cache_provenance.py` | (module, not a command) | the shared `file_provenance()` / `source_set_hash()` / `verify_source_set()` used by the two above. **An extraction, not an invention**: all seven envelope parsers already compute this hash and agree exactly, and the suite holds this module to byte parity with all seven — if a parser's formula ever drifts, that parity goes red rather than the gate silently reporting every cache stale forever. A domain hashes **only the files it reads**, never the whole savegame |
| `lint_append_only.py` | `sanctum/history/delta-log.jsonl` + `scripts/` | **the three teeth that police the append-only delta log** — **static** (no shipped script opens a history-class path for writing), **watermark** (line count never decreases, first line's digest never changes — one catches a tail truncation, the other a head truncation, and neither catches both), **chain** (`seq` contiguous, every `prev_source_set_hash` resolves). A break that a **gap record explains** is not a failure; an unexplained one is. ⚠ **A lost watermark makes tooth 2 `UNCHECKABLE`, which exits non-zero — never a pass.** "I could not check" and "I checked and it was fine" are different answers |
| `delta_log.py` | (module, not a command) | the **append-only history** — `sanctum/history/delta-log.jsonl`, newest-last, one entry per generation, chained by `prev_source_set_hash`. **This is the only artifact in the system that cannot be regenerated**: everything else dies with `rm -rf cache/` by design, which is why it lives under the sanctum and carries the only `"a"`-mode writer. **Gaps are never filled, interpolated or smoothed** — a break emits an explicit `gap` record and any rate computed across it must be refused. `delta-log.watermark.json` is a **high-water register: `line_count` only ever rises, and it is never rotated** — a watermark that can go down is a mirror, and a mirror cannot detect the truncation it is mirroring |
| `aggregate_render.py` | (module, not a command) | the **aggregate view + in-process claims manifest** behind `read_state.py`'s `--render-only` / `--emit-claims`. Flat, one level, generated wholesale, **never persisted**. **No authored prose at all** — every string it emits is a structural label or a value copied from the cache, which makes **the note-contradicts-its-flag defect** (a note asserting a match its own boolean denies) structurally impossible rather than merely fixed. Every rendered figure is registered as a claim naming its file and `json_path`, and **every claim is re-resolved and compared before a single line is emitted**; a mismatch yields `CLAIM UNRESOLVED` and **no view**. A failed section renders **more prominently, not less**; a long list is summarised **with an explicit pointer, never silently truncated** |
| `cache_layout.py` | (module, not a command) | cache placement, `CACHE-VERSION`, atomic writes (temp file is always a **sibling** of its target — `os.replace` is atomic only within a filesystem), and **the one farm-id boundary**: config's `farm_id` is normalised to `int` exactly once, in one direction, because the live config carries the string `"1"` while an envelope carries the integer `1` and `"1" == 1` is False. Also `paths_escape_savegame()`, which asserts the published read-only promise on the **resolved** paths rather than on the sibling-directory convention |
| `wait_for_event.py` | (polls) the savegame + replies.xml | **the event watcher** — under a persistent Monitor it emits one line per settled write, so the manager idles at ~zero token cost until the game writes. Poll not inotify (WSL#4739); savegame keys on mtime+size vs a persisted marker, replies on content (empty file = processed) so the truncate can't self-loop or lose a reply. Armed at briefing, disarmed at closeout. Exit `0` = clean stop, `1` = failed arm / crash (`ERROR` line) |

`read_store_prices.py`, `read_game_defs.py` and `read_equipment_market.py` locate the
install/mods dirs via `sanctum/config.json` → `paths`, resolved from the working directory —
run them from the project dir, or pass `--config`/`--install-dir`/`--mods-dir`.
`read_farmland_areas.py` locates its mods dir the same lookup but resolved by walking up from
the **script's own install location**, not the working directory, and it has no `--config`
flag — pass `--mods-dir` explicitly if it doesn't find a `sanctum/config.json` above it.
`farm_snapshot.py` finds that config itself and accepts `--config`; without it the sections
that need the game install report themselves `unavailable` with the reason, and the
savegame-only sections are unaffected.

**A crop is a SELL calendar; an input is a BUY calendar.** For grain a *high* price is good;
for seed, fertilizer, lime and herbicide a *low* price is good. Never run both through one
"find the best price" step — that inverts the advice and recommends buying seed at its annual
peak. `read_game_defs.py` decides which is which from the game's own data, so a map that adds
its own input is classified correctly with no code change. Some inputs are **flat all year**
(no timing play exists — a real answer, not missing data); others swing by multiples, and a
low can be a **one-period window**. Buying a low only helps if the farm owns storage to put it
in — `farm_snapshot.py`'s `input_costs.can_stockpile` gates that on real owned storage rather
than assuming it.

## The FARM tab's figures are published for you, not by you

`scripts/emit_farm_xml.py` writes `modSettings/FS25_AIFarmManager25/<savegameKey>/farm.xml`
beside `cards.xml` on every refresh, and the mod's FARM tab renders it — one file in
`modSettings/`, never the savegame. It carries the **as-of** groups only: land, productions and
fleet. **Money and contracts are read LIVE by the mod from the engine** and are never written
there — a field-tied contract's reward is computed by the game at accept-time and is not in the
save at all, so a file figure would be a stale number sitting behind a row the tab labels LIVE.
A row whose parser failed is simply absent and the tab shows `unknown`; the refresh reports what
degraded, so **do not report a publish carrying `notes` as a clean one**.

The FARM tab's **Low fuel** row is the count of vehicles in `farm_snapshot.build_fleet`'s severe
fuel tier (≤25%, the same function behind your fuel alert), joined against the tank capacity from
the store-XML pass. If some fuel-carrying vehicle's tank could not be resolved (encrypted DLC) the
count is a **lower bound** and the tab reads `N+`; if none could be measured it is `unknown`. The
emitter takes the game install from the `--config` it is handed — `refresh_state.py` passes it —
and a run without one publishes no fuel figure and reports a note instead of "Low fuel 0".

## Used-equipment listings — a decision, not a bargain hunt

`read_equipment_market.py` resolves every second-hand listing against the same machine's real
*new* price, so a discount you quote is a measured figure rather than the seller's framing, and
condition rides beside it: **wear, damage and hours run**. **Listings expire**, so each carries
the time left on it — a recommendation that ignores that is advice the player cannot act on. A
listing whose machine could not be matched is reported as **unresolved, with the reason** —
never dropped, because a shorter list of bargains is not the same answer as a complete one.
